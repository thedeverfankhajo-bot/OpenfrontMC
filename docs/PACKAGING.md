# PocketMine API 5 packaging

OpenFrontMC ships as a PocketMine-compatible plugin PHAR. Its ready-to-use
world pack is generated by booting the current Axolotl-PM server (a maintained
PocketMine-MP fork that supports API 5 plugins), allowing OpenFrontMC to create
and render its managed worlds, and shutting the server down cleanly.

## Runtime choice

The original `pmmp/PocketMine-MP` repository was archived in July 2026.
This project therefore uses Axolotl-PM, an actively maintained fork which
continues the PocketMine-MP 5.x line. Axolotl-PM keeps the `pocketmine\\`
namespaces, plugin loader and `plugin.yml` format. Plugins declaring
`api: [5.0.0]` load on Axolotl-PM 5.x unless they depend on the network API.
OpenFrontMC does not directly use the PocketMine network API.

Axolotl-PM retains PMMP's world format and server data layout, so its LevelDB
worlds and plugin data use the same folder structure.

## Tools

- PHP CLI with `phar`, `yaml`, and `sqlite3` extensions for PHAR building
- Composer (for the project test and static-analysis scripts)
- `curl`, `tar`, `unzip`, and `zip`
- The Axolotl-PM installer and its version-matched bundled PHP runtime
- The official PocketMine DevTools source, used to create the plugin PHAR

Runtime binaries are downloaded during installation rather than committed to
Git, avoiding large OS-specific executable files.

## Build the plugin

From the repository root:

```sh
composer install
composer test
composer analyse
bash tools/build-phar.sh dist/OpenFrontMC.phar
```

The script stages only `plugin.yml`, `src/`, and `resources/` and invokes the
DevTools `ConsoleScript.php`. It validates that the resulting PHAR contains
the manifest, main class, and default configuration.

## Install the API 5 server

Run the installer in a separate server folder (not the repository root):

```sh
bash tools/install-pocketmine.sh .runtime/pocketmine
```

This installs the latest stable Axolotl-PM release and its matching PHP binary
into the requested directory. The installer is intended for Linux/macOS; for
Windows, use the Axolotl-PM Windows installation instructions.

## Generate the ready world pack

Use a clean, disposable server directory. The server must not already contain
an OpenFrontMC world or plugin data directory.

```sh
bash tools/build-world-pack.sh .runtime/pocketmine dist
```

The builder copies `dist/OpenFrontMC.phar` into the server, starts it with the
setup wizard disabled, waits for the map renderer completion message, and
then stops the server cleanly. It verifies both Bedrock LevelDB world folders
and checks that all 256 default territories are rendered in the matching
SQLite database.

The output `dist/OpenFrontMC-WorldPack.zip` contains:

- `worlds/openfront_lobby/` (LevelDB)
- `worlds/openfront_world/` (LevelDB)
- `plugin_data/OpenFrontMC/` (matching SQLite map data and configuration)

The ZIP includes the SQLite metadata because the plugin uses it to track
territories and whether the physical map has already been rendered. Installing
only the world folders would cause a newly-created database to rebuild the map.

## Restore a world pack

Install Axolotl-PM and place the matching `OpenFrontMC.phar` in `plugins/`.
Then, while the server is stopped:

```sh
bash tools/install-world-pack.sh dist/OpenFrontMC-WorldPack.zip .runtime/pocketmine
```

The installer refuses to overwrite an existing OpenFrontMC world or data
directory. Back up live server files before replacing any world.

## GitHub Actions artifacts

The `Package API 5 plugin and world` workflow produces:

- `OpenFrontMC.phar` — installable OpenFrontMC plugin
- `OpenFrontMC-WorldPack.zip` — pre-rendered LevelDB worlds plus matching plugin data
- `Axolotl-PM-API5-Linux-x86_64.tar.gz` — server PHAR, start script, bundled
  PHP runtime, OpenFrontMC plugin PHAR, and server properties for Linux x86_64

The server-runtime archive is Linux x86_64 only. For other systems and
architectures, use the Axolotl-PM installer on the target machine.
